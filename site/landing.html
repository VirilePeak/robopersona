Behavior packages for embodied AI.

A .botpack bundles a persona manifest, payload files and a SHA-256 index into one integrity-checked archive. Its affect engine is specified to return bit-identical IEEE-754 doubles in Rust, Python and WebAssembly for the same sequence of operations. CI checks all three runtimes against a published fixture.

One archive, fixed order

A .botpack is a zstd-compressed tar. The entry order is normative.

PositionEntryContent
firstmanifest.jsonIdentity and persona (§3)
middlepayloadAny files: prompts, configs, assets (§5)
lastchecksums.jsonSHA-256 of every payload entry (§4)
  • Readers recompute every digest and reject the archive on a mismatch, a missing digest or an extra one.
  • Readers reject path traversal, absolute paths and reserved names inside the payload.
  • Readers reject a foreign major format_version and ignore unknown fields within a major.
  • Ingested manifest bytes are stored verbatim, so unknown fields survive a round trip (§3.4).

Reference scenario: baseline {{baseline}}, decay rate λ = {{decay_rate}}, max step {{max_step}}, one stimulus {{stimulus}}, then {{tick_count}} ticks of {{dt}} s. A conforming runtime ends in exactly these bits:

valence    {{valence_bits}}

Each value is f64::to_bits() as 16 lowercase hex digits. The inputs are pinned as bit patterns too: {{dt}} is not exactly representable, so the fixture fixes {{dt_bits}}. Decimal renderings are non-normative.

CI checks the same file from Rust (f64::from_bits), Python (struct.unpack(">d")) and Node via wasm (DataView, big-endian). Fixture: affect-reference.json. Contract: §7.

Quickstart

The latest release ships CLI binaries for macOS arm64 and Linux x86_64 plus a SHA256SUMS file.

BIN=botpack-aarch64-apple-darwin      # Linux: botpack-x86_64-unknown-linux-gnu
curl -fLO https://github.com/VirilePeak/robopersona/releases/latest/download/$BIN
curl -fLO https://github.com/VirilePeak/robopersona/releases/latest/download/SHA256SUMS
shasum -a 256 -c SHA256SUMS --ignore-missing   # Linux: sha256sum -c SHA256SUMS --ignore-missing
chmod +x $BIN && mv $BIN botpack             # then put it on your PATH

The Linux binary needs glibc 2.34 or newer (Ubuntu 22.04+, Debian 12+). The macOS binary is not notarized: download it with curl as above. A copy downloaded in a browser is quarantined, and Gatekeeper refuses to run it. Or build from source:

cargo install --git https://github.com/VirilePeak/robopersona --locked botpack

A package is a directory with a manifest.json. Everything else in it becomes payload:

$ mkdir -p atlas/prompts
$ printf '%s' '{"format_version":"{{spec_version}}","name":"atlas-caretaker","version":"0.1.0","persona":{"display_name":"Atlas Caretaker","languages":["en"]}}' > atlas/manifest.json
$ echo "Hello. I keep the aisles clear." > atlas/greeting.txt
$ echo "You are a careful warehouse robot." > atlas/prompts/system.txt
$ botpack pack ./atlas -o atlas.botpack
packed ./atlas -> atlas.botpack
$ botpack verify atlas.botpack
OK atlas-caretaker v0.1.0 (format {{spec_version}}) — 2 payload entries
$ botpack unpack atlas.botpack -o ./out && diff -r atlas out && echo identical
verified + extracted 2 entries -> ./out
identical

Status

  • Format {{spec_version}} is a draft. Breaking changes are gated by the major version (§9).
  • checksums.json detects corruption, not tampering: whoever can rewrite the archive can rewrite the index. Signatures are not part of {{spec_version}}.
  • One implementation so far: a Rust core with Python and wasm bindings. The fixture is there so that a second, independent implementation can check itself against it.
  • Prebuilt binaries for macOS arm64 and Linux x86_64 only.

Issues, questions and independent implementations: GitHub issues.
